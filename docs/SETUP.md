# KnowYourCode — Setup Guide

## Prerequisites

- Node.js **18.17+** (developed on 20/24)
- npm 9+
- A GitHub account with access to the repositories you want to analyze

## 1. Install

```bash
npm install
```

## 2. Environment variables

Copy the example file and fill in your keys:

```bash
cp .env.example .env
```

| Variable           | Required | Description                                                                  |
| ------------------ | -------- | ---------------------------------------------------------------------------- |
| `GITHUB_TOKEN`     | Optional | GitHub personal access token. Needed for higher rate limits / private repos. |
| `CLAUDE_API_KEY`   | Optional | Anthropic API key. Without it the AI features use a built-in fallback.       |
| `CLAUDE_MODEL`     | Optional | Claude model name. Defaults to `claude-3-5-haiku-latest`.                    |
| `NODE_ENV`         | Optional | `development` or `production`.                                               |

> **Never commit the real `.env` file.** Only `.env.example` is tracked.

### GitHub token (recommended)

The app reads **public** repositories without a token, but GitHub's
unauthenticated rate limit is 60 requests/hour. Analyzing a few repositories
or running quizzes repeatedly will exhaust it. To avoid this:

1. Create a token at https://github.com/settings/tokens — no scopes are needed
   for public repositories.
2. Set it as `GITHUB_TOKEN` in `.env`.

For **private** repositories, the token needs the `repo` scope. Git
credentials are not used; only the token.

### Claude API key (recommended)

Get a key at https://console.anthropic.com. Without it, explanations, quizzes,
and interview replies are generated by a deterministic, dependency-free
fallback engine (still functional, but less natural).

## 3. Run in development

```bash
npm run dev
```

Open http://localhost:3000, paste a GitHub repository URL, and press
**Analyze Repository →**.

## 4. Production build

```bash
npm run build
npm start
```

## 5. Scripts

| Command             | Description                       |
| ------------------- | --------------------------------- |
| `npm run dev`       | Development server.               |
| `npm run build`     | Production build.                 |
| `npm start`         | Run the production build.         |
| `npm run lint`      | Run ESLint (via `next lint`).     |
| `npm run typecheck` | Run `tsc --noEmit`.               |

## 6. Deployment (Vercel)

The app is a single Next.js project — frontend and API routes deploy together.

1. Push the repository to GitHub.
2. Import it at https://vercel.com/new.
3. Add the environment variables from `.env.example` in the project settings.
4. Deploy. The included `.github/workflows/deploy.yml` also builds on every
   push to `main`.

## Troubleshooting

**"Could not analyze repository"** — the repository is private and no token is
set, the token is invalid, or the URL is malformed. Confirm the URL matches
`https://github.com/user/repo` and that the token (if any) has access.

**"Could not fetch ... from owner/repo"** — the file path in the tree could
not be read. This usually means the file was renamed between the tree listing
and the fetch; retry.

**Slow analysis on large repositories** — line counts are estimated from a
sample of up to 40 text files. Large monorepos take longer; a token speeds up
rate-limited fetches.

**GitHub rate-limit errors (403)** — add a `GITHUB_TOKEN`. The app issues one
request for the metadata, one for the file tree, and one per sampled file.
